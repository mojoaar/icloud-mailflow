# v0.7.0 Design Spec

## Overview

Single major release bundling rules engine enhancements (body/header/date matching), new rule actions (forward, delete, remove_flag), infrastructure improvements (IMAP health, activity log search, poller status), 6 new MCP tools, and UX polish (mobile, loading indicators, auto-refresh, inline rule delete confirm).

---

## 1. Rules Engine Enhancements

### 1.1 Body Matching

**Files:** `internal/imap/client.go`, `internal/rules/engine.go`, `internal/imap/message.go`

Add `body` as a condition field. When a rule uses `body`, the engine fetches plain-text body content from IMAP.

**IMAP client additions:**
```go
FetchMessageBody(uid uint32) (string, error)
```
Uses `BODY.PEEK[TEXT]` fetch item. Returns plain text as `string`. No MIME parsing or HTML stripping.

**Engine changes:**
- `getFieldValue()`: add `"body"` case — calls `client.FetchMessageBody(uid, section)`
- Only called during `Evaluate()` when a field starts with `"body"`
- Existing string operators (contains, equals, not_equals, starts_with, ends_with, matches_regex) work without changes

### 1.2 Header Matching

**Files:** `internal/imap/client.go`, `internal/rules/engine.go`

Add `header:X-Name` field format for arbitrary IMAP header matching.

**IMAP client additions:**
```go
FetchMessageHeader(uid uint32, headerName string) (string, error)
```
Uses `BODY.PEEK[HEADER.FIELDS (X-Name)]` fetch item. Returns header value as `string`.

**Engine changes:**
- `getFieldValue()`: detect `header:` prefix, extract header name, call `FetchMessageHeader()`
- Zero overhead when no header fields in condition groups (lazy fetch)
- All existing string operators apply

### 1.3 Date Matching

**Files:** `internal/imap/message.go`, `internal/rules/engine.go`

**Message struct change:**
```go
type Message struct {
    UID     uint32
    Envelope *goimap.Envelope
    Date    time.Time  // new — from Envelope.Date
    // ... existing fields
}
```

**New operators:**
| Operator | Syntax | Behavior |
|---|---|---|
| `older_than` | `older_than N days` | `time.Since(msg.Date) > N * 24h` |
| `newer_than` | `newer_than N days` | `time.Since(msg.Date) < N * 24h` |
| `before` | `before YYYY-MM-DD` | `msg.Date.Before(parsed)` |
| `after` | `after YYYY-MM-DD` | `msg.Date.After(parsed)` |

**Engine changes:**
- `evaluateCondition()`: add numeric/time operator dispatch alongside existing string operators
- Date parsing: `time.Parse("2006-01-02", value)` for before/after, `fmt.Sscanf` for older_than/newer_than

### 1.4 fetchBodyForRule

`Evaluate()` gains optional pre-fetch: if a rule has body/header conditions, fetch body/headers once before evaluating individual conditions. Avoids repeated IMAP round-trips per condition.

```go
messageCache := map[uint32]*messageExtras{}
// messageExtras holds Body string, Headers map[string]string
```

## 2. Rule Actions

### 2.1 Forward Action

**Files:** `internal/imap/client.go`, `internal/poller/poller.go`, `internal/smtp/smtp.go`

New action type `"forward"` with param `"recipient"`.

**IMAP client additions:**
```go
FetchRawMessage(uid uint32) ([]byte, error)
```
Uses `BODY.PEEK[]` (full RFC822). Returns raw MIME bytes.

**Workflow:**
1. Fetch raw MIME via `FetchRawMessage(uid)`
2. Extract `MessageID` from original headers for `In-Reply-To` / `References`
3. Construct forward email via `smtp.Send()`:
   - Subject: `Fwd: <original subject>`
   - Body: `message/rfc822` MIME attachment containing the original
   - Sender: IMAP account email
   - Recipient: from action params

**SMTP changes:** `Send()` already supports attachments via `internal/smtp/smtp.go`. May need `SendRaw` variant that accepts pre-built MIME bytes.

### 2.2 Delete Action

**Files:** `internal/poller/poller.go`

New action type `"delete"` — no params needed.

**Workflow:**
1. Find Trash folder: iterate `ListFolders()` results for folder with `\Trash` flag
2. Cache result in poller struct field `trashFolder string` to avoid repeated IMAP calls
3. `MoveMessage(uid, trashFolder)` — iCloud requires `\Seen` first (already guaranteed by action ordering)
4. Fallback: if no `\Trash`-flagged folder, case-insensitive match for "Deleted Messages"

### 2.3 Remove Flag Action

**Files:** `internal/poller/poller.go`

New action type `"remove_flag"` with param `"flag"`.

Calls `client.RemoveFlags(uid, []string{flag})`. Existing IMAP call at `internal/imap/client.go:192` — no IMAP changes needed.

Validate flag starts with `\` or matches known keywords (`Seen`, `Flagged`, `Answered`, `Draft`).

### 2.4 Poller Switch Changes

Add three new cases to `executeActions()` switch alongside existing `move_to_folder`, `mark_as_read`, `mark_as_unread`, `set_flag`.

## 3. Infrastructure

### 3.1 IMAP Connection Health

**Files:** `internal/poller/poller.go`

**New Poller fields:**
```go
lastError          atomic.Value   // stores error or nil
consecutiveFailures int           // guarded by mu
backoff            time.Duration  // current backoff value
imapConnect        func() (imap.Client, error)  // factory from main.go
```

**Backoff sequence:** 5s → 10s → 20s → 40s → 60s (cap). Resets to 0 on successful operation.

**Flow:**
1. Any IMAP operation fails → increment `consecutiveFailures`, store error in `lastError`
2. Any IMAP operation succeeds → reset `consecutiveFailures` to 0, clear `lastError`
3. `consecutiveFailures > 2` → pause polling, start reconnect:
   - Wait `backoff` duration
   - Call `imapConnect()`
   - On success: reset state, resume polling
   - On failure: double backoff (capped at 60s), retry
4. New method: `PollingHealthy() bool` returns `consecutiveFailures == 0`

**main.go changes:** Pass IMAP connect factory to `NewPoller()`:
```go
poller.NewPoller(cfg, db, func() (imap.Client, error) {
    return imap.Connect(cfg.IMAPEmail, cfg.IMAPPassword)
}, ...)
```

### 3.2 Activity Log Search & Pagination

**Files:** `internal/db/log.go`, `internal/web/activity.go`, `internal/web/templates/activity.html`

**New DB method:**
```go
func (r *LogRepo) ListFiltered(limit, offset int, search, rule, status string) ([]LogEntry, int, error)
```
Returns entries + total matching count. SQL with conditional WHERE:
- `search`: `WHERE (subject LIKE ? OR sender LIKE ? OR rule_name LIKE ?)` with `%term%`
- `rule`: exact match on `rule_name`
- `status`: `WHERE status = ?` ("ok" or "error")

**Template changes (activity.html):**
- Search input with `hx-get="/activity" hx-trigger="keyup changed delay:300ms" hx-target="#activity-table"`
- Rule filter dropdown (populated from rules list)
- Status filter: All / Success / Error buttons
- Page size selector: 25 / 50 / 100 (default 50)
- Prev/Next buttons with page indicator: "Page 1 of 5"

**Handler changes (activity.go):**
- `activityPage`: parse query params `q`, `rule`, `status`, `page`, `per_page`
- Return filtered results + pagination metadata in template data

### 3.3 Poller Dashboard Status

**Files:** `internal/web/templates/dashboard.html`, `internal/web/dashboard.go`

**New endpoint:** `GET /dashboard/status` — returns partial HTML

**Poller additions:**
```go
func (p *Poller) Status() PollerStatus  // thread-safe snapshot
type PollerStatus struct {
    Active             bool
    Healthy            bool
    LastTick           time.Time
    LastError          string
    LastDuration       time.Duration
    ProcessingMessages bool
    ConsecutiveFailures int
}
```

**Template changes (dashboard.html):**
- Reconnect banner (yellow/red): "IMAP disconnected. Retrying in Xs..." — shown when `!Healthy`
- Last result line: "Last poll: 2m ago — OK (3 messages processed)" or "Last poll: 5m ago — Error: connection reset"
- Duration: "Duration: 1.2s"
- Spinner: `.htmx-indicator` shown when `ProcessingMessages` is true

**HTMX auto-refresh:**
```html
<div hx-get="/dashboard/status"
     hx-trigger="every 30s"
     hx-swap="innerHTML"
     hx-indicator=".status-spinner">
  <!-- status content -->
</div>
```
Only the status card auto-refreshes. Rules table and buttons stay static.

## 4. MCP Tools

**Files:** `internal/mcp/server.go`

### 4.1 New Tools

**enable_rule / disable_rule:**
```json
{"name": "enable_rule", "params": {"rule_id": 1}}
{"name": "disable_rule", "params": {"rule_id": 1}}
```
Toggle `enabled` field via `rulesRepo.Update()`. Returns updated rule JSON or error.

**get_poller_status:**
Returns JSON with running state, last tick, last error, consecutive failures. Uses `poller.Status()`.

**import_rules:**
```json
{"name": "import_rules", "params": {"rules": "[{...}, {...}]"}}
```
Parses JSON array, calls `rulesRepo.Create()` for each. Returns count imported. Same format as `backup_rules` output.

**list_contacts:**
Returns `contactsRepo.ListAll()` results as JSON. No params.

**clear_activity:**
Calls `logRepo.DeleteAll()`. Returns success. Stats unaffected.

**seed_contacts:**
Calls `collector.SeedFromFolder()`. Returns count added. No params.

### 4.2 Updated Factory Signature

```go
func New(d *sql.DB, imapClient imap.Client, rulesRepo *db.RulesRepo,
         logRepo *db.LogRepo, statsRepo *db.StatsRepo, contactsRepo *db.ContactsRepo,
         foldersRepo *db.FoldersRepo, poller *poller.Poller,
         collector *contacts.Collector, settingsRepo *db.SettingsRepo) *Server
```

Total: 12 existing + 6 new = **18 tools**.

### 4.3 Caller Changes

**internal/web/web.go:**
```go
mcpServer := mcp.New(database, imapClient, rulesRepo, logRepo, statsRepo,
    contactsRepo, foldersRepo, poller, collector, settingsRepo)
```

## 5. UX

### 5.1 Mobile Responsiveness

**New file:** `internal/web/static/mobile.css`

```css
@media (max-width: 768px) {
    /* tables: horizontal scroll */
    /* cards: stacked, full-width */
    /* nav: stacked vertical, visible always */
    /* forms: full-width inputs */
    /* buttons: full-width, min 44px touch targets */
    /* emails: word-break: break-all */
}
```

Linked in `base.html`: `<link rel="stylesheet" href="/static/mobile.css">`

### 5.2 Loading Indicators

**New CSS:** Added to existing `style.css` or `mobile.css`:
```css
.htmx-indicator { display: none; }
.htmx-request .htmx-indicator { display: inline-block; }
```
Animated spinner via CSS `@keyframes spin` on a border-based circle.

**Buttons updated:**
- "Seed Contacts" — wraps text in `<span class="htmx-indicator">`
- "Run Poll Now" — same pattern
- "Backup Now" — same pattern
- "Import Rules" — same pattern

Add `aria-busy="true"` toggle via HTMX's `hx-indicator` attribute.

### 5.3 Dashboard Auto-Refresh

See Section 3.3. `/dashboard/status` endpoint serves partial template. HTMX `hx-trigger="every 30s"` on status card container.

### 5.4 Rule Confirmation Dialogs

**Files:** `internal/web/templates/rules.html`, `internal/web/rules.go`, `internal/web/web.go`

**Current behavior:** Delete link navigates to `/rules/{id}/delete` confirmation page → POST confirms deletion.

**New behavior:** Inline HTMX-based confirmation:
```html
<button hx-delete="/rules/{id}"
        hx-confirm="Delete this rule?"
        hx-target="closest tr"
        hx-swap="outerHTML">
    Delete
</button>
```

**Changes:**
- Add `r.Delete("/rules/{id}", deleteRule)` route to web.go (returns 200 OK, no body)
- `deleteRule` handler calls `rulesRepo.Delete(id)`, returns empty response (row removed by HTMX)
- Remove: `rules_delete.html` template
- Remove: `confirmDeleteRule` handler
- Remove: `GET /rules/{id}/delete` route

## 7. Testing Strategy

- **Rules engine:** Table-driven tests for body, header, date conditions. Mock IMAP client returns canned body/header values.
- **Actions:** Mock IMAP client + Mock SMTP sender for forward. Poller tests for delete folder detection + remove_flag.
- **IMAP health:** Unit tests for backoff sequence, reconnect trigger at failures > 2, reset on success.
- **Activity log:** DB integration tests for `ListFiltered` with various filter combinations.
- **MCP:** Test each new tool via `mcp.CallTool()` with mock repos.
- **UX:** Visual verification via browser for mobile, spinners, confirm dialogs. HTMX behavior tested manually.
